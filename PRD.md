# Product Requirements Document (PRD): zer0-kernel

> A hobby operating-system kernel in C, booted with Multiboot2 on QEMU.

Open work is tracked in [GitHub Issues](https://github.com/bamr87/zer0-kernel/issues) and as `status: planned` entries in [features/features.yml](features/features.yml).

## 1. Overview

From the boot sector up: a freestanding C kernel that boots under QEMU, then grows memory management, interrupts, a scheduler and a tiny shell.

| Version | Date | Notes |
| --- | --- | --- |
| 0.1 | 2026-10-28 | Initial requirements and phased roadmap (repo foundation). |

## 2. Goals

- Multiboot2 kernel that boots in QEMU and prints to VGA/serial
- Interrupts, paging and a physical frame allocator
- Preemptive scheduler and a minimal shell

Non-goals (near term): production hosting, paid services, anything outside the roadmap below without a PRD change.

## 3. Users

- The maintainer, learning freestanding c and linker scripts, x86_64 boot, paging and interrupts by building.
- Fleet agents (hub evolution loop, backlog fan-out, `evolve` lane) that grow the repo one reviewed PR at a time.
- Fleet tie-in: Systems-depth companion to bashos and kvlite; the zer0 brand's lowest layer.

## 4. Requirements

Phases are the build order: an agent picks the earliest unserved requirement first.

### 4.1 Phase 1 — Foundation

- FR1: Freestanding kernel object and Multiboot2 header build with host gcc/ld via make
- FR2: Kernel ELF links with a linker script and boots in QEMU (grub-mkrescue ISO)

### 4.2 Phase 2 — Core

- FR3: Serial and VGA text output drivers
- FR4: IDT, exceptions and timer interrupts

### 4.3 Phase 3 — Fleet integration

- FR5: Paging and physical frame allocator
- FR6: Round-robin scheduler and a minimal shell

### 4.4 Non-functional

- NFR1: CI (`.github/workflows/ci.yml`, the fleet standard gate) passes on every PR.
- NFR2: No secrets or credentials are committed; configuration comes from environment variables.
- NFR3: Autonomous lanes are off by default, open pull requests only, and never merge.
